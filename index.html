Mixed Composability of Modular SPARQL Parsing and Query Execution

Jitse De Smet, Ruben Taelman

IDLab, Department of Electronics and Information Systems, Ghent University – imec, Ghent, Belgium

Problem

  • The SPARQL ecosystem is fragmented: engines introduce valuable but incompatible language extensions.
  • This undermines query portability, tooling reliability, and the pace of innovation.
  • SPARQL 1.2 will widen the gap further, requiring substantial updates to datasets and RDF stores.

Approach

  • Traqula: a modular, builder-based SPARQL parser framework with dynamic grammar extension and strong typing.
  • Comunica: a modular query engine with a component-based, dependency-injection architecture.
  • Mixed composability: combining parser modularity with engine modularity for a flexible SPARQL pipeline.

Traqula: Modular Parser

  • Builder pattern for composing SPARQL parsers from modular grammar fragments.
  • Rules registered by name with loose coupling — extend, patch, or delete individual rules.
  • Type-safe: integration errors caught at compile time through TypeScript generics.
  • Pre-built engines for SPARQL 1.1 and 1.2, with composable building blocks.

Comunica: Modular Engine

  • Highly modular query engine using dependency injection via Components.js.
  • Actors and mediators enable swapping components without touching others.
  • Integrates Traqula parsers as swappable components, enabling custom SPARQL dialects per engine.
  • Monorepo of small, focused packages for flexible builds (web, CLI, custom).

Web Demonstration

Our interactive web demo showcases four live grammar modifications, starting from a SPARQL 1.1 parser:

  • Extend: add ADJUST function support (Oxigraph-style)
  • Add: CONSTRUCT QUAD queries (Jena-style)
  • Integrate: full-text search scoring (Virtuoso-style)
  • Remove: OPTIONAL clause to reduce query complexity

Each modification demonstrates modular grammar changes with minimal effort and full type safety.

The demo illustrates how parser and engine composability complement each other, enabling a new generation of language-aware SPARQL tools.
