A State-Based Add-Wins CRDT for RDF Datastores

Jitse De Smet, Ruben Taelman

IDLab, Department of Electronics and Information Systems, Ghent University – imec, Ghent, Belgium

Problem

  • Autonomous agents increasingly write to shared RDF knowledge graphs concurrently — one enriches, another reasons, a third corrects.
  • In decentralized data ecosystems (Solid, IDSA, Gaia-X), participants govern their own data without a central authority.
  • Concurrent offline editing causes write conflicts when agents reconnect — manual conflict resolution is undesirable for agents.
  • Existing RDF CRDT approaches either require dedicated infrastructure (m-ld) or introduce consistency boundary problems by storing bookkeeping across multiple resources.

Approach

  • Instantiate the state-based OR-Set CRDT over RDF 1.2 triple terms — triples can appear as objects of other triples.
  • All bookkeeping stays within a single dataset — no external blobs or dedicated servers needed.
  • Add-wins semantics: concurrent add and remove of the same triple always keeps the triple.
  • Transparent to agents: CRDT-aware datastore plugs into query engines — agents use standard SPARQL, unaware of merge machinery.

State-Based OR-Set in RDF 1.2

  • Each triple carries a set of unique add-tags (UUIDv4); removing moves tags to a tombstone set.
  • An identifying blank node links each tracked triple (via crdt:tags), its add-tags, and tombstones using RDF 1.2 triple terms.
  • A triple is present when it has ≥1 add-tag not in its tombstone set.
  • On merge, multiple identifying nodes for the same triple are consolidated into one.

Web Synchronization

  • State-based merge aligns with HTTP's REST semantics — exchanging full dataset state rather than operations.
  • ETag + conditional PUT (If-Match) avoids mid-air collisions — no additional infrastructure beyond what most Web servers already provide.
  • CRDT-aware store implements RDFjs Store interface — plugs into Comunica for transparent SPARQL queries.
  • CRDT-aware and CRDT-unaware clients coexist: unaware clients can still read the data.

NTP Tombstone Optimization

  • Tombstones accumulate indefinitely without garbage collection — a fundamental CRDT challenge.
  • NTP guarantees max drift of 1000s; between two synchronized clients: max 2000s difference.
  • Tags stamped with crdt:stamp-uuid ({uuid}--{dateTime}) enable time-based pruning.
  • A tag is universally seen once older than d + 4000s — then safe to prune.
  • Works in open ecosystems where replica sets are unknown — unlike prior approaches requiring causal delivery.

Conclusion & Future Work

  • State-based add-wins set CRDT modelled entirely in RDF 1.2 — no infrastructure beyond RDF-over-HTTP with ETag support.
  • Eliminates the consistency boundary problem — all bookkeeping within the dataset itself.
  • Conflict resolution fully transparent to agents and SPARQL clients alike.
  • PoC implementation: orset-rdf-store on npm.
  • Future work: constraint-aware merge semantics — two valid states can merge into a state violating domain constraints.
