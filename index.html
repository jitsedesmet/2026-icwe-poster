An Add-Wins OR-Set CRDT for Conflict-Free RDF Datastores

Jitse De Smet, Ruben Taelman

IDLab, Department of Electronics and Information Systems, Ghent University – imec, Ghent, Belgium

Problem

  • Multiple clients need to read and write the same RDF graph concurrently — even while offline.
  • Concurrent edits cause write conflicts that traditional stores cannot resolve without coordination.
  • Existing approaches require always-online coordination, blocking offline-first and decentralized use cases.

Approach: OR-Set CRDT

  • Every added triple is tagged with a unique UUID identifier.
  • Removing a triple records the UUIDs of all observed add-tags at removal time.
  • Add-wins semantics: concurrent add and remove of the same triple always keeps the triple.

Self-Contained Data Model

  • CRDT metadata stored inline as regular RDF quads using RDF 1.2 triple terms (quoted triples).
  • Each data triple has a blank-node tagger linked via crdt:tagging to a triple term.
  • A triple is visible if at least one of its add-tags is not covered by any remove-tag.
  • Entire state serialized as N-Quads — self-contained, no external metadata needed.

Web Synchronization

  • WebSyncedStore extends the CRDT store with automatic periodic HTTP pull/push.
  • Uses ETags and conditional PUT (If-Match) to detect mid-air collisions.
  • RDFjs-compliant — works as source and destination for Comunica SPARQL queries.
  • Compatible with any Solid server or ETag-aware HTTP storage.

Add-Wins Guarantee

Key Features

  • State-based merge: commutative, associative, idempotent
  • Offline-first: reconcile later without conflicts
  • Tombstone expiration: prevent unbounded growth
  • SPARQL via Comunica: INSERT / SELECT / DELETE
  • npm: orset-rdf-store

Future Work
