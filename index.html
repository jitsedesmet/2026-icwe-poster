A State-Based Add-Wins CRDT for RDF Datastores

Jitse De Smet, Ruben Taelman

IDLab, Dept. of Electronics and Information Systems, Ghent University – imec

Key Features

  • Heterogeneous interfaces — minimizing requirements on participating stores
  • Interact with KGs and decentralized data ecosystems through standard SPARQL
  • Atomicity through self-containment — bookkeeping in a single RDF dataset
  • Serving both CRDT-aware and CRDT-unaware clients transparently

Heterogeneous Interfaces

Conflict-Free RDF Replication using Web Standards

RDF 1.2 Data Model

Data Model Properties

  • RDF 1.2 triple terms — CRDT bookkeeping embedded directly in the RDF graph
  • NTP-bound optimization
    • Drop old & redundant add-tags
    • Drop old tombstones safely
  • Max NTP allowed drift: ≤ 2 000 ms — safe pruning after d + 4 000 s

Design Choices

  • Add-wins semantics — concurrent add + remove always keeps the triple
  • RESTful state-based design — exchange full state, no operation logs
  • ETag for mid-flight collision detection with If-Match on PUT
