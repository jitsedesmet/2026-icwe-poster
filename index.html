A State-Based Add-Wins CRDT
for RDF Datastores

Jitse De Smet, Ruben Taelman

IDLab, Department of Electronics and Information Systems, Ghent University – imec, Ghent, Belgium

Problem

Concurrent writes to shared RDF graphs
Decentralized — no central authority
Offline editing → write conflicts
Existing: extra servers or boundary problems

Approach

OR-Set CRDT over RDF 1.2 triple terms
All in one dataset — no blobs
Add-wins: add + remove → keeps triple
Transparent to SPARQL agents
Conflict-free RDF replication using only standard Web infrastructure

State-Based OR-Set in RDF 1.2

  • Each triple carries add-tags; removal → tombstone set
  • Blank node links triple term + tags via crdt:tags
  • Present ⟺ ≥1 add-tag not in tombstones
  • Merge consolidates nodes for same triple

Web Synchronization

  • REST-aligned — exchange full state
  • ETag + PUT prevents mid-air collisions
  • RDFjs Store → Comunica SPARQL
  • Aware + unaware clients coexist

NTP Tombstone GC

  • NTP drift ≤ 2000s
  • stamp-uuid → time-based pruning
  • Safe prune after d + 4000s
  • Open ecosystems — no replica set

Conclusion

  • CRDT modelled entirely in RDF 1.2
  • No boundary problem
  • PoC: orset-rdf-store

Future work

  • Constraint-aware merge
  • Valid states can merge into constraint-violating states
