A State-Based Add-Wins CRDT
for RDF Datastores

Jitse De Smet, Ruben Taelman

IDLab, Dept. of Electronics and Information Systems, Ghent University – imec

1 The Problem

  • Autonomous agents write concurrently to shared RDF knowledge graphs
  • Decentralized ecosystems (Solid, IDSA, Gaia-X) have no central coordinator
  • Offline editing leads to divergent states and write conflicts
  • Existing CRDTs suffer a consistency boundary problem or require extra servers

2 Our Approach

  • OR-Set CRDT modelled in RDF 1.2 triple terms
  • Bookkeeping in one dataset — no opaque blobs
  • Add-wins semantics: concurrent add + remove keeps triple
  • Transparent to standard SPARQL agents

3 RDF 1.2 Data Model

  • Each triple has add-tags (UUIDs); removal adds tags to tombstone set
  • A blank node links a triple term to its tags via crdt:tags
  • Triple is present iff ≥1 add-tag is not in tombstones
  • Merge = union of add-tags, union of tombstones, consolidate per triple

4 Web Synchronization

  • State-based — exchange full state, no log shipping
  • ETag + If-Match prevents mid-air collisions on PUT
  • Any RDF-over-HTTP endpoint (e.g. Solid pod)
  • CRDT-aware and unaware clients coexist

5 Tombstone GC

  • NTP drift bound ≤ 2 000 ms
  • stamp-uuid encodes timestamp
  • Safe pruning after d + 4 000 s
  • Works in open ecosystems

6 Conclusion

  • CRDT modelled entirely in RDF 1.2
  • No consistency boundary problem
  • PoC: orset-rdf-store

7 Future Work

  • Constraint-aware merge
  • Valid states can merge into constraint-violating states
Conflict-free RDF replication using only standard Web infrastructure — no extra servers, no boundary problem.
